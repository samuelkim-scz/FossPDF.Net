# FP-002 Windows validation

Recorded October 26, 2026, for [FP-002 / issue #3](https://github.com/samuelkim-scz/FossPDF.Net/issues/3), on `feature/fp-002-native-backends-adr` based on main commit `e9bee81`.

Environment: Windows x64, .NET SDK 9.0.305, .NET 9.0.21 runtime, SkiaSharp 3.119.4, HarfBuzzSharp 8.3.1.5.

## Prototype results

| Prototype | Result | Evidence |
| --- | --- | --- |
| SVG input | Passed | Svg.Skia 4.9.1 rendered a 240x140 SVG; four sampled pixels matched; the PNG was placed in a one-page FossPDF PDF |
| Existing-PDF operations | Passed | PDFsharp 6.2.4 imported two Skia-generated PDFs, reordered pages to widths `[300, 200]`, left the caller-owned output stream open, and the output reopened with two pages |
| Semantic tagging | Passed as a structural prototype | PDFsharp `UAManager`/`StructureBuilder` produced a `StructTreeRoot`, document structure element, `/StructElem`, `/MarkInfo`, `/MCID`, `/ParentTree`, `BDC`/`EMC` operators and a reopenable one-page PDF |
| Build | Passed | Prototype project built with `--warnaserror`: 0 warnings, 0 errors |
| Artifacts | Written | `prototype-results.json`, SVG/PNG, source/reordered PDFs and `tagged-structure.pdf` |

`prototype-results.json` is generated by the run. The tagged PDF is **not** a PDF/UA or PDF/A
conformance claim; no validator was run and no tagged-structure semantics were reviewed.

## Dependency resolution

- Svg.Skia 4.9.1 resolves transitively to Svg.Animation/Custom/Model/SceneGraph/ShimSkiaSharp 4.9.1,
  ExCSS 4.3.1, SkiaSharp and HarfBuzzSharp. The prototype pins the core's SkiaSharp 3.119.4 and
  HarfBuzzSharp 8.3.1.5 over Svg.Skia's declared 3.119.2/8.3.1.3.
- PDFsharp 6.2.4 resolves to Microsoft.Extensions.Logging.Abstractions 8.0.3,
  Microsoft.Extensions.DependencyInjection.Abstractions 8.0.2 and
  System.Security.Cryptography.Pkcs 8.0.1. All are MIT and managed.
- **Licence finding:** `Svg.Custom 4.9.1` is MS-PL, not MIT. Svg.Skia is therefore prototype-only
  pending a reviewed MS-PL notice/acceptance decision; the core package remains MIT. See
  [NATIVE_DEPENDENCIES.md](../NATIVE_DEPENDENCIES.md).
- PDFsharp is MIT at 6.2.4 and includes the UniversalAccessibility structure API. No separate
  commercial accessibility package was required for the prototype.

## Ownership and cleanup observations

- SVG: `SKSvg` and the rasterization surface were disposed deterministically; no system-font
  dependency was needed for the shape-only SVG.
- PDF operations: PDFsharp left the caller-owned `MemoryStream` open after `Save`; imported documents
  and pages were disposed after the reordered document was written.
- Tagging: a custom `IFontResolver` loaded the bundled `Lato-Regular.ttf`/`Lato-Bold.ttf`, so Linux and
  macOS do not need Arial or system fonts. The language was set to `en-US`; structure elements were
  paired with `End()` calls.

## CI matrix

The `native-prototypes` job runs the same project on Windows, Linux and macOS and uploads
`fp-002-native-prototypes-<OS runner>` artifacts. The prototype project is outside `FossPDF.sln`, is
not packed, and is not referenced by the production library.

## Reproduce

From `Source`:

```powershell
dotnet restore FossPDF.NativePrototypes/FossPDF.NativePrototypes.csproj
dotnet build FossPDF.NativePrototypes/FossPDF.NativePrototypes.csproj -c Release --no-restore --warnaserror
dotnet run --project FossPDF.NativePrototypes/FossPDF.NativePrototypes.csproj -c Release --no-build --no-restore -- --output ../artifacts/fp-002
```

## Limitations

- Only Windows x64 has been observed locally; the Linux/macOS runs are CI evidence.
- The tagging prototype verifies structural markers and re-openability, not PDF/UA or PDF/A
  conformance. veraPDF (or equivalent) and human accessibility review remain in FP-401/FP-403.
- The SVG prototype uses shapes only. Text/SVG-font behaviour and preloading semantics remain FP-201.
- PDF encryption, signatures, attachments, XMP and page-range semantics remain with FP-302–FP-306.
- The prototype does not measure performance or memory; those measurements belong to the owning
  feature issues and the FP-003 quality baselines.
